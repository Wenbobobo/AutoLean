## 这份清单解决什么问题

AutoLean 可以写代码、跑确定性测试、安排多个彼此隔离的模型角色互相挑错；但它不能靠自己悄悄
获得教材许可、判断 Lean 公式是否等价于原文、证明某个独立主机确实执行过操作、控制云服务商的
扣费上限，或宣布一个数学结果是新的。本文件把这些边界放在一个地方。

未勾选的项目只会阻止它写明的那种“接受效果”，不会阻止无关的离线开发、资料发现、假模型测试
或隔离区研究。反过来，绿色测试、多个模型一致、或者系统自己写的报告，也不能单独勾选任何
权威项目。

### 优先级与支持类型

优先级按当前关键路径排序，不是按个人感受或事项本身是否重要排序。

| 优先级 | 数量 | 现在的含义 |
| --- | ---: | --- |
| P0 | 2 | 第一条真实教材命题进入“冻结合同”前必须完成。 |
| P1 | 2 | 大规模运行或完整安全/公开闭环之前要完成；现在可以并行准备。 |
| P2 | 3 | 现在准备，等有冻结合同后才有真正的执行意义。 |
| P3 | 3 | Phase 1 退出阶段或暂停候选；不要抢占 P0 资源。 |
| P4 | 2 | 产品或开放问题的远期决定。 |
| 机械完成 | 1 | 可重放的确定性证据已经足够，不需要人工判断。 |
| 当前不需要人工 | 5 | 现有的保守策略或自动化已足够，直到触发条件真的发生。 |

“人工决定”表示需要有人对范围或数学含义负责。“外部操作”表示一个独立控制的主机、服务商或
签名器要执行并保留一个限定动作；部署后可以自动化。“当前不需要人工”表示应按既定的保守策略
继续，而不是为了形式上的“找专家”停掉机器工作。

## 给非数学背景读者的总览

最短且诚实的路径是：先决定 iFEM 教材资料可以怎样使用；再写出一条精确命题；确认它的 Lean
表述没有改变原文含义；最后让一个独立控制的 Lean 环境运行这条不变的合同。Lean 证明只能回答
“这个形式化句子能否推出”，不能回答“它是不是把教材的话翻对了”。因此，来源权限和命题保真
必须排在 Prover 接受结果之前。

旧的模型论候选目前明确是 `gap/not_selected`（有缺口、未选中）。它不是当前最快路径。把它保留为
反例/负样本不需要数学专家；只有将来要重新启用它时，才需要专家审查。

### [ ] AUTH-RIGHTS-01 - 批准来源专属的版权/使用范围与模型外发范围

- **支持类型 / 优先级：** 来源/权利决定，P0。
- **通俗解释：** 决定哪些文字可以复制、保存、公开展示、发送给外部模型。这是许可和出处问题，不是

- **完成后的作用：** 在所选范围内解锁第一批真实 `local_calibration` 样本。
- **现在不完成会怎样：** Agent 只可查看公开元数据、使用合成样本；不得把正文发给外部模型、公开再分发，

- **需要什么帮助：** 项目/来源权利责任人选择一个窄范围。近期建议是“本地缓存分析、保留署名、不得

### [ ] AUTH-T5-01 - 批准并冻结一条精确的命题合同

- **支持类型 / 优先级：** 数学语义决定，P0；在权利范围确定之后。
- **通俗解释：** 确认一条 Lean 句子确实表达了一条来源句子的意思，包括“对所有”“边界条件”和
  例外情况。冻结表示 Prover 只能尝试证明这条原样句子，不能悄悄改题。
- **当前状态：** 还没有真实来源驱动的命题被批准或冻结。系统已有机器候选、反向翻译、变异测试、
  反例和异议记录，但它们被故意限制为 `machine_advisory`。
- **完成后的作用：** 这是 Builder 交给 Prover 的真正关口。不通过它，Lean 解出的可能根本不是教材
  原题。
- **现在不完成会怎样：** 可以继续发现、研究和非冻结的本地校准；不得路由到 Prover 接受，也不得说
  它代表教材。
- **需要什么帮助：** 独立承担责任的语义审查者（或未来另行批准、版本化的更窄策略）查看小型审查包：
  来源段落、白话复述、Lean 命题、假设/量词、正反例、变异结果、imports 与 axioms。这里数学专长很
  有用，因为一个很小的措辞改动就可能把结论反过来。
- **完成证据：** 精确合同版本/哈希、来源/权利记录、审过的形式化 profile、独立决定、全部异议处置、
  freezer 身份和失效/复核日期。只对该版本生效。

  axiom/dependency 审计、内核重放和独立复现。
- **完成证据：** 冻结的猜想版本、验证/复现回执、带日期的检索记录、审查决定以及允许的精确公开
  表述；永远不自动覆盖相邻命题。

## 安全、数据与事件支持

### [ ] AUTH-INCIDENT-01 - 关闭历史 Hugging Face 凭据事件

- **支持类型 / 优先级：** 外部安全操作，P1。
- **通俗解释：** 删除归档只关闭了一个传播途径，不能证明旧 token 在其他地方已经失效。
- **当前状态：** 项目所有者已确认删除 HF 归档。当前提交和可达历史扫描保护候选仓库，但服务商侧的
  凭据状态尚未独立记录。
- **完成后的作用：** 降低历史暴露 token 被再次用于公开基础设施的风险。
- **现在不完成会怎样：** 使用新秘密引用的本地开发可继续，但不能诚实宣称事件已完全关闭。
- **需要什么帮助：** 各凭据所有者到相应服务商账户检查，并撤销或轮换可能暴露的 HF、GitHub、
  OpenAI/Codex 和兼容端点凭据。这是账户操作，不是把秘密写入仓库的请求。
- **完成证据：** 服务商、凭据标识或权限范围（绝不写值）、撤销/轮换日期、责任人和证据引用。不要在此
  写 session 名、prompt 或原始归档事实。

## 如何记录完成

每个勾选的权威事项，都要追加一条带日期的决定记录：

```text
决定：
承担责任的所有者或独立操作员：
优先级与适用范围：
证据引用和 SHA-256：
允许产生的接受效果：
它不证明什么：
失效或复核日期：
```

绝不在本文件写入凭据值、私有来源摘录、原始模型回答、私有路径、session 归档、签名密钥或未脱敏
prompt。任何完成记录只能授权写明的效果，不能悄悄削弱 Builder -> 冻结合同 -> Prover 的边界。
